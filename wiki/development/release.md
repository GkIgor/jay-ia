# Releases

## Estado atual

Ainda não existe processo formal de release.

## Direção

Enquanto o projeto estiver em fase de definição, cada marco relevante deve priorizar:

- atualização da wiki
- consolidação de ADRs
- clareza de fase e PRD

## Critério de prontidão atual

Antes de tratar algo como marco importante do projeto, verificar:

- a visão continua coerente
- os ADRs relevantes existem
- as especificações mínimas foram escritas
- a fase correspondente está clara
- o impacto sobre a arquitetura foi registrado

## Evolução futura

Quando o projeto passar a ter entregas executáveis, este documento deverá separar:

- marcos documentais
- marcos internos de arquitetura
- versões utilizáveis do Core
- versões utilizáveis de frontend

## Regra

Nenhum release futuro deve contradizer decisões arquiteturais formalizadas sem atualização correspondente da wiki.
